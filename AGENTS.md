# Working in dregg-assortia

Read README.md, intent.md, and the latest dated orientation before making project-wide recommendations.

- Git is the primary VCS. Fossil is an undecided issues/discussion candidate.
- This is an orientation workspace. A graph record is an assertion with provenance, not authority over a sibling repository.
- Inspect a claim's actual source and relevant local instructions before editing a sibling. Preserve unrelated working-tree changes. Do not build the whole suite to orient.
- Separate user intent, historical user instructions, agent inference, source inspection, test source, captured run, and current live observation.
- Distinguish models, implementations, artifacts, receiving consumers, deployments, and parameter/configuration scope. Do not infer one from another.
- A replacement is not a completed cutover until its intended consumers use it. A receipt of intent is not evidence that external I/O occurred.
- Record contradictions only after comparing their scopes and revisions. Missing evidence means unknown. A changed source hash means recheck.
- The initial JSON-LD vocabulary is a specimen. Change it when a real question needs a better representation; do not build an exhaustive ontology or import every Markdown sentence.
- Keep source facts in graph.jsonld. Narrative orientations are dated interpretations. If tools or storage are added, decide which representation owns each kind of fact and derive other views.
- Candidate work items are proposals, not assignments or accepted priorities. Each needs a concrete closure condition and links to the capability it advances.
- Bound agent tasks by a question and a receiving consumer. Reports must say what was read/run and what remains uncertain.
- Do not copy private profiles, credentials, entire unrelated transcripts, or operational secrets into this project. Session excerpts here concern DREGG design/work only.
