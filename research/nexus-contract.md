## Five decisions to take

1. **Resource identity is independent of its locator, renderer and agent session; revisions and occurrences are explicit.** Publish a versioned family/interface identity and typed resource reference; distinguish follow-current, exact-version citation and independent branch. Content, executable behavior and presentation may be separate cells, but a usable composition pins exactly which versions it runs. Editing a rendered tool must commit the behavior/presentation consumed on reopen. Do not derive a version from a URL or conflate an object root, semantic root and history-entry root. Existing source makes these distinct in `Theory/Hyperdocument.lean:415` (`StoredSourceIdentity`), `:455` (`StoredTransclusionRef`), and `:524` (`VersionEventRecord`). `LinkTarget.external` at `:465` already permits external addresses without claiming local ownership. This is an appropriate source vocabulary, not a completed naming/network service.

2. **Human and Hermes requests exercise the same current, request-indexed authority.** Preserve the complete request (semantic domain/relation, federation, subject/key epoch, typed target/verb, argument/effect digests, nonce, pre-root, policy/epoch and cost), not an `authorized: true` result. Interface negotiation is discovery/admission preparation; it grants neither a hidden object handle nor execution completion. `Theory/TypedAuthorization.lean:88` defines the request; `Theory/HyperdocumentInterface.lean:281` and `:303` retain exact authorization and pre-root but no post-state. Actions reuse the existing Hyperdocument declaration (`:265`). A release transport needs an exact lawful codec and family-selected argument binding; a JSON wrapper cannot supply a competing mutation implementation. Extending the nexus means extending the existing family/derived path when necessary, not installing arbitrary server callbacks as new semantic authority.

3. **One operation has one authoritative accepted patch/history path; multi-resource composition declares its boundary.** `Theory/AcceptedCellEffect.lean:57` supplies family-specific declarations, outcomes, evidence and a unique patch; `:85` joins authorization and validated patch. Pair its common binding with `AcceptedCellEffectRequestBinding` as D-0002 requires. `Kernel/TypedCellHyperedge.lean:32` projects authority from the same cell; `Kernel/MultiCellHyperedge.lean:39` admits heterogeneous schemas/materializers/authority projections, and `:121` requires all legs. Preserve family laws rather than interpreting every resource as an integer map. Multi-cell source has per-incidence exact pre-cells, not one universal shared root. Physical all-or-nothing persistence remains an explicit handler/refinement obligation (`MultiCellHyperedge:172`, `:218`); reject/blocked/unknown must not masquerade as committed state. Decide and test the acknowledgment promise, duplicate request handling and crash recovery on the actual receiving store.

4. **History retains concurrent alternatives and the basis on which they were admitted; settlement uses current authority.** An offline draft/branch can retain its own history without being accepted as the shared current head. Reconnection imports evidence, checks authority and publishes a merge or explicit conflict; it must not silently equate stale capability possession with current permission. Keep pinned citations stable while live views advance explicitly. `Hyperdocument.lean:403` stores conflict alternatives with provenance and makes resolution a later authority-sensitive operation; `:524` keeps final causal events in a separate append-only cell, including parents and exact roots/request/effect. This supports a contract choice; it does not establish physical offline replication or a ready merge UI. Avoid imposing generic last-writer-wins just because the interface needs one status label.

5. **External operations retain the external protocol's authority and evidence rule.** A hosted job, Solana custody action or Clutch purchase is a typed operation resource with causally linked intent, dispatch/attempt, observed result and accepted completion/refusal. Transport delivery, execution assertion, verified correctness and external finality remain distinct observations. The common contract binds the operation identity, source resource revisions, actor, external domain/object, exact statement and evidence policy; the family defines what success means. For public jobs, separately name resource offer, provider obligation, stake-lock evidence, input/program revision, result/checker, deadline/challenge rule, verdict and reputation effect. A timeout is not an incorrect-result proof. A real-lock devnet penalty records its own nonmonetary event and leaves custody balance unchanged; release/withdrawal remains a custody decision. Personal cell hosting does not automatically enroll its operator as a bonded job provider. These are proposed application contracts grounded in the recorded intent and provider inventory, not a claim that any reviewed runtime already supplies the entire route.

## Stress test of the interface

| Meaning | Document + authored tool | Hosted public job |
|---|---|---|
| Shared identity | Document/version, behavior/presentation revision, request and receipt | Job, pinned program/input revisions, request and receipt |
| Shared authority mechanism | Observe/edit/install/delegate exact target under current policy | Advertise/accept obligation/submit evidence/adjudicate under distinct scopes |
| Family-specific law | Citation source, merge/conflict semantics, accepted behavior change | Capacity/deadline, objective output checker or bounded dispute, custody terms |
| Completion evidence | Accepted patch + content/history durable publication | Provider reply alone is pending evidence; selected verifier/verdict authorizes completion effect |
| Recovery | Restore the same content, behavior and causal events another user saw | Reconcile dispatch/retry/result without duplicate reward, verdict or reputation consequence |

The shared waist does not collapse document conflicts into job faults, DREGG receipts into Solana finality, or hosting capability into token custody. Conversely, separate families do not excuse separate authoring identities, ad hoc authorization booleans or history that merely reports an unrelated runtime mutation.

## Candidate acceptance journey, not a selected application

A friend creates a resource containing a document and an inspectable small tool. A second friend uses the same typed interface from another renderer, then changes the tool's declared behavior/presentation and reopens it. Real external Hermes receives a scoped delegation and makes one authorized change; the second friend observes that exact committed revision. An attempted cross-resource call and a revoked/stale shared commit are refused without changing the committed resource.

The second friend branches on a genuinely separate local device/process, edits offline, reconnects and sees either an explicit conflict or an explained merge with both parents. A pinned citation still presents its original source. A participant-operated node serves one named resource under the same identity and authority contract.

To exercise outward growth, the tool submits one deliberately bounded public job over its pinned input/program revisions. A contributed provider accepts it under a named service obligation and verified real-token lock (if provider scope is selected). A correct result and an invalid-result or timeout case follow the declared evidence rules. The accepted output becomes a linked resource revision; an adjudicated devnet penalty changes the reputation record without reducing the bond. Restart the receiving host across an interrupted dispatch/commit and retry the request: committed resource/history and economic observations agree, and no result or penalty duplicates. The chosen custody operation must have a real external chain outcome consumed by this path; holding observation alone is insufficient.

This is a composition workload, not a demand to pick a fieldbook or job market as the product. For September 26, select a coherent subset only after naming the actual consumer of every operation. If public providers are out of scope, replace the economic leg with one selected Clutch/payment operation while retaining its own protocol evidence and consuming the result in the resource world.

## Follow-up: a public-document transform as the illustrative job

A deterministic index or render transform over pinned public inputs is a good *candidate* stress workload: participant two hosts it, and its output becomes a linked document/resource. It exercises authoring, own-node service, reproducibility and actual result consumption without selecting a workroom genre. Its usefulness and exact checker still need selection; this pass established neither a landed transform nor a verifier. Recommend the provider bond only if this service is genuinely useful and a bounded check/dispute rule is chosen, consistent with the economic review. Otherwise choose a needed payment connection; do not invent a Clutch claim simply to display a transaction.

Actual semantic constraints: `Theory/HyperdocumentOperations.lean:79` has a closed action grammar (create, editAtom, link, transclude, mark, annotate). These actions can represent/publish the source/output and its links; they do **not** by themselves define arbitrary tool execution, program installation or output correctness. `SemanticEffectFamily` supports family-selected declarations/outcomes/mode evidence/patches, so the required transform should use an existing compatible computation family after exact inspection, or widen the Lean-owned family vocabulary and derived consumer. A `program` resource kind or manifest name alone supplies no executor. Input identity, tool version, canonical codec and exact output relation must be bound; recomputation/checking must validate that relation, not merely the provider's nonempty bytes or output hash assertion. A stored link to the result and an accepted result-verification effect are distinct legs.
