# $DREGG-only OpenRouter and homelab inference: Bread reuse audit

**Status, September 27:** source inspection and a proposed integration slice. No payment, provider request, bot message, test run, deployment, or graph change was made. The user's “chonga” was informal slang, not a provider or product name. Users buy credits from us with **$DREGG only**, then spend those credits on real OpenRouter models or local homelab models. Discord is an interface alongside hosted Hermes and shell. The operator's OpenRouter credential, allowed model IDs, pricing and usage schedule, and local model catalog still need to be pinned.

## What exists

- `dregg-pay/src/watcher.rs:602–705` implements a process-stateless `SignatureWatcher` over finalized inbound Solana transfers, using `soltx:{signature}` as the stable payment reference. `discord-bot/src/pay.rs:1745–1780` selects its default **$DREGG** asset for the real watcher. `discord-bot/src/main.rs:1018–1052` chooses a watch-only address book when configured, otherwise a custodial/devnet constructor. The watcher validates transaction/account shape supplied by the RPC; this is not by itself a light-client proof of Solana finality.
- `dregg-pay/src/ledger.rs:193–287` prices a payment into run credits, deduplicates by payment reference, and debits a credit. The bot persists balances and processed references in SQLite `pay_credits`/`pay_processed` (`discord-bot/src/db.rs:686–706,1084–1129`). The library's price/treasury abstractions also cover USDC (`dregg-pay/src/pricing.rs:276–315`, `treasury.rs`), so a new product must bind its own credit SKU to observed **Asset::Dregg** rather than inherit a generic dual-asset balance. These credits are an off-chain custodial service ledger, not Mini-conserved value.
- `narrator/src/openai.rs:55–110` implements a blocking OpenAI-compatible chat-completions call with configured endpoint, Bearer key, and timeout. `narrator/src/backend.rs:233–260` performs price lookup, USD reservation, provider call, then true-up/refund; `narrator/src/ledger.rs:234–305` persists a per-call USD cap. `discord-bot/src/pay.rs:590–685` wraps it with operator treasury fuel and deletes the per-run budget file afterward. This transport supports operator-configured OpenAI-compatible endpoints, including OpenRouter, but an explicit operator model, price, and usage contract is still needed.
- Bread already has a BYO-key OpenRouter endpoint/profile (`discord-bot/src/llm_provider.rs:1–115`) and a local Ollama fallback (`narrator/src/narrator.rs:32–75,259–264`). Those paths establish protocol reuse, not a DREGG-paid product or current homelab model availability. Discord has `/buy-credits` and `/credits` (`discord-bot/src/commands/pay.rs`) and a separate BYO-key channel chat path (`discord-bot/src/hermes_channel.rs:625–829`). The BYO-key path authorizes a token-budget turn and optionally calls the user's provider; it does not spend operator-purchased $DREGG credits. Existing dungeon narration is game-specific, including a 25-second UI deadline (`commands/descent.rs:2835–2885`); it should not become the general inference authority.
- Mini already has a distinct hosted provider task, metered reserve/settlement, retained pending state, and hard-disconnect reconciliation (`minidregg/native/grain-runtime/src/main.rs:2593–2699,6204–6770`). The shared inference operation should join that custody path for hosted Hermes/shell instead of creating a second untracked provider executor in the bot. Discord is another client to the same service boundary.

## Gaps that matter before paid calls

`discord-bot/src/pay.rs:86–103` implements only `balance`, `set_balance`, `is_processed`, and `mark_processed` for `SqliteCreditStore`. It inherits `CreditStore::credit_once` and `debit_one` defaults (`dregg-pay/src/ledger.rs:39–63`), which perform separate read/write/mark steps; the SQLite setter ignores write errors. The ledger's Rust mutex protects one handle, not two processes or the multi-table transaction. Thus the comments describing atomic persisted credit/dedup/debit exceed this adapter's actual guarantee. Make both operations one checked SQLite transaction before allowing $DREGG purchases of inference credits.

`PayState::credit_holds` is an in-memory `HashSet` (`discord-bot/src/pay.rs:978–986,1127–1166`). That is deliberate for the existing dungeon run: process death releases a hold without charging the player. It does not preserve an inference request across process death or another frontend. The narrator deletes its per-run USD ledger (`pay.rs:623–638`). A provider error currently refunds the reservation (`narrator/src/backend.rs:233–260`) even when transport failure could follow remote execution. Discord's 25-second `timeout(spawn_blocking(...))` abandons waiting but does not prove the HTTP call stopped. A generic inference product therefore needs a durable request ID, held credit, provider-send phase, exact result/usage, and an **uncertain** state that can be reconciled without an automatic second paid request. User credit and operator USD fuel are separate books; neither a Discord timeout nor a model response is a payment receipt.

## Small connected implementation slice

1. Define one operator service API for a bounded `infer(requestId, user, model, prompt, maxTokens)` and `lookup(requestId)`. Route each permitted model to an operator-held OpenRouter profile or an available homelab endpoint, with explicit model identity, cost bounds, credential handling and usage semantics. Discord, hosted Hermes, and shell all address the same service and receive the same retained result/uncertainty classification. Bot credentials and payment watcher remain outside the model worker.
2. Add SQLite transactions for **$DREGG-only** payment crediting and reserve/commit/release of one product credit, with a unique request ID and immutable payment reference. Keep the old dungeon credits separate unless an explicit migration maps them. Before network I/O, record the hold and operator budget reserve; after a complete provider response, store the exact usage/result and settle once. A lost reply keeps the request held/uncertain for lookup. Process death/restart reopens the same state.
3. Connect the service's model leg to Mini's existing provider-task custody and hard-disconnect semantics. Reuse the existing OpenAI-compatible Rust parser for the OpenRouter route; keep homelab model execution and cost accounting explicit. Begin with a local deterministic provider and payment fixture: duplicate signature, two frontends racing one credit, timeout after send, restart, exact lookup, and no second provider send. Then add a thin Discord command/channel adapter with defer-first responses and bounded output. No paid OpenRouter call is needed for this first slice.

This is a scope recommendation, not an implementation claim. The open inputs are the operator OpenRouter credential and model/price/usage policy, plus the homelab model catalog and availability contract. Current Mini SPK/native preview lanes remain untouched.
