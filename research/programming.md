# Kernel programming and shell integration — 2026-09-17

Ember explicitly accepts a mixed first offering, provided it has DREGG-kernel programmability / integration with a programmable shell at some level. This investigation distinguishes programmable rules, effect-producing scripts, computation and OS command execution. It does not choose a new language, renderer or receiving runtime.

Two Astra lanes inspected minidregg and breadstuffs programming paths. The parent checked the shell routes and the load-bearing source excerpts below. No code was built or executed, and no sibling repository was changed. The source paths are candidates for a receiving implementation, not evidence of a working release.

## Breadstuffs: cell rules are user-authored data

`CellProgram::Predicate` and `CellProgram::Cases` are serializable transition rules. Cases combine guards such as method, effect kind and changed slot with state constraints. New combinations within this vocabulary can be constructed by a client without rebuilding the host; adding a new evaluator primitive is different work. These programs validate proposed transitions rather than generating the effects themselves. See [the types](/Users/ember/dev/breadstuffs/cell/src/program/types.rs:6).

The ordered `SetProgram` effect rewrites a cell's program. The executor requires program-identity authority (`SetVerificationKey`) on the target and applies the update through its journal. Touched-cell program evaluation is part of ordinary action execution; failures become `ProgramViolation`. Relevant source: [authorization](/Users/ember/dev/breadstuffs/turn/src/executor/authorize.rs:2647), [application](/Users/ember/dev/breadstuffs/turn/src/executor/apply.rs:1400), [evaluation consumer](/Users/ember/dev/breadstuffs/turn/src/executor/execute_tree.rs:640).

This is a useful programming mechanism with distinct receiving obligations. The installed Lean constraint oracle decides a defined subset; the evaluator retains named non-Lean witness/crypto/executor-state cases, and an undecided Lean-subset request must refuse under the selected oracle policy ([evaluator](/Users/ember/dev/breadstuffs/cell/src/program/eval.rs:337)). `SetProgram` is outside the native producer's wire coverage: the actual [mappability match](/Users/ember/dev/breadstuffs/exec-lean/src/lean_shadow.rs:1057) falls through to false. The node records an existing named [Rust fallback](/Users/ember/dev/breadstuffs/node/src/executor_setup.rs:571) for outside-coverage turns. This describes the present implementation; it does not establish the selected release path or justify changing producer mode.

The rotated witness guard classifies `SetProgram` as an `UnprojectedMover`: it has neither a VM row nor an after-cell projection binding the program-authority write ([projection guard](/Users/ember/dev/breadstuffs/turn/src/rotation_witness.rs:1208)). The [sovereign producer consumes that classification](/Users/ember/dev/breadstuffs/sdk/src/cipherclerk.rs:5537) and returns `InvalidWitness` before cohort dispatch. Closing this route therefore requires native wire/reconstitution coverage and the coordinated VM, witness and after-state binding, not just a shell command. A specific full-turn node installation path was not exhaustively traced. See [the full breadstuffs investigation](breadstuffs-programming.md).

A separate programmable object is `CircuitDescriptor`: `POST /programs/deploy` decodes serialized descriptors, validates and persists a registry snapshot, then publishes it to live executors. Its scope is explicitly authenticated **node-local administration**, not a consensus-ordered user installation ([deployment handler](/Users/ember/dev/breadstuffs/node/src/api.rs:8887)). The Astra trace located a registry-descriptor-to-IR2 verifier consumer in the sovereign atomic executor ([consumer](/Users/ember/dev/breadstuffs/turn/src/executor/atomic.rs:1203)), but did not establish a complete newly authored descriptor → cell VK installation → proof production → canonical finalized turn journey. Descriptor deployment alone neither computes an application result nor establishes that the proof statement is sufficient.

`Effect::Custom` is a different mechanism again: its registry contains host verifier callbacks. It should not be promoted into arbitrary user-program installation merely because its name says custom.

## Design consequence and next check

The leading composition to evaluate is **authored cell rules + effect-producing scripts + an explicitly connected shell**. A mixed collection of resources can use that common path. The release still needs a specific choice of rule vocabulary, program representation, authority, runtime and durable acknowledgment; existing module names do not settle those choices.

The proposed integrated acceptance exercise is: author a rule as data, install it on an owned resource through the chosen authority path, invoke a permitted operation from the shell, then attempt a violating operation. Verify the accepted resource/history and the refusal's unchanged state, including restart. The first check must establish how the intended node producer and proof mode handle installation. A refusal caused by missing projection is an implementation obligation to close, not permission to disable proving or switch to a weaker path. The minidregg action interpreter can also be checked narrowly before integration, without invoking its unary codec; such a semantic check does not by itself meet the release acceptance exercise.

These are proposed next checks; none was run in this source pass. The new-tool-without-host-rebuild criterion remains an assistant acceptance proposal. Ember's accepted requirement is the mixed programmable environment and shell connection.

Ember's subsequent sprint instruction makes the disposition of these findings explicit: implement the missing support across the necessary stack, including substantial core work. A missing feature is an implementation obligation; it is not a reason to route around the intended kernel or weaken its guards. The active implementation investigations are tracked in [the sprint record](../sprints/2026-09-17.md).
