## Shared implementation target

A person authors behavior/rules as data, installs or changes them under resource authority, invokes them through a programmable shell or Hermes, and obtains the intended kernel's accepted transition or refusal. Accepted content, behavior and history survive restart and become visible to another authorized participant. Local replicas and participant-operated hosts use the declared authority, identity and history contracts.

This is a proposed integrated acceptance journey, not a restriction to one application genre or one effect vocabulary. Core changes may extend the language, canonical carrier, compiler, proof statement, verifier, storage protocol and every consuming interface as required. Refusing guards remain in place until their actual missing guarantees are implemented.

Minidregg's accepted [D-0002](/Users/ember/dev/minidregg/docs/decisions/D-0002-canonical-hyperedge-kernel.md) selects canonical typed cell effects and flat multi-incidence turns. It is the current design starting point, not proof that its artifact and runtime consumers are complete. Existing breadstuffs modules supply reusable mechanisms and compatibility obligations; preserving the old call forest is not an assumed constraint on the new core.

## Integration rules

- Keep one explicit semantic contract for each selected operation and list its actual producers and consumers. Give each lane concrete file ownership; shared schema changes require coordination.
- Implement the missing guarantees needed by the accepted experience. Do not disable an oracle, fall back silently, copy state into a parallel demo ledger, or weaken a statement to make an integration pass.
- Name a refusal, success and recovery check at the actual receiving boundary. Proof checking, test source, captured execution and live deployment are different evidence.
- Reassess scope from integrated results. Ember's reported cycle capacity and core-work percentage support substantial work but are not evidence that a particular bundle is complete.
- Record corrections to our own source map when stronger traces contradict it. An unchanged source hash preserves bytes, not the correctness of the earlier interpretation.
