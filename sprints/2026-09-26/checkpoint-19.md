A source review identified two corrections before native dispatch can be built.
An ordinary participant should exercise a signed current session witness and
observe the serving app under a separate current Mini grant. Giving that
participant an app mutation grant just to issue a request risks authorizing
lifecycle edges. Mini's `ResourceObservationAdmission` can check the app's
actual loaded page and current observe grant, and `DurableDataIntent` can retain
an exact read guard and a distinct dispatch event/nullifier. The accepted event
is the durable pending intent; a generic content-journal target could be
written or occupied by an ordinary invocation. This is a reviewed design, **not
yet an implemented receiver**. The committed candidate command still contains
the provisional app and journal targets; its own comments explicitly deny
delivery authority. A scoped correction is underway.

Session role assignment already represents none, all-access, role ID and
added/removed permissions. Mini `6f945ab` extends the typed RPC adapter to
retain exact ordered `ViewInfo` permission definitions, roles, default and
obsolete flags, raw role bitsets and denied bits, with a bounded fake-peer test.
The installed Mini app manifest still lacks a canonical role/default table and
resolver. Exact effective bits cannot yet be derived and no incoming request
may be treated as admitted. The
Simple Todos specimen declares no external HTTP API, so a second real package
or an evidenced API route is still needed for browser-plus-agent acceptance.
