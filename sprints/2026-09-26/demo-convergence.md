## The first coherent experience

Two friends enter a shared project. One asks hosted unforked Hermes to make a
concrete project change through the actual GitWeb app API; the other opens the
same persistent packaged application in a browser and sees that change. They
can also inspect and operate the underlying Mini resources with direct commands.
Read-only access permits reading and refuses writing. Reconnecting returns to
the same resources. An explicit publish operation sends selected project bytes
or a version to a separately governed node over fn.

GitWeb is the current grounded integration candidate, not a claim that push,
browser identity and agent compatibility already work. If actual package behavior
invalidates a needed interaction, record that evidence and select another real
package with the required interfaces. Do not substitute a toy app or merely
display an agent's prose as evidence of an application change.

application/resource lineage; isolated fixtures remain useful regressions, not
substitutes for these outcomes. Root owns the one integration driver and final
demonstration contract. A lane's delivery includes its receiving caller and a
runnable acceptance step, not merely a new author/inspect helper.

## Changed working discipline

1. Use a canonical resumable journey and retained stage outputs. Verify the
   previous operation before resuming; never restart all bootstrap as a debugging
   reflex or turn an uncertain response into another submission.
2. Batch compatible source changes into one qualified native build. Reuse exact
   certified build prefixes with the existing guards. Keep at most two Lean
   processes globally and independent writable caches.
3. Report user-visible acceptance, actual blocker, next integration action and
   cold/warm timings. A module count or test count alone is not a milestone.
4. Address the measured creation bottleneck before treating a longer deadline
   as usability. Measure creation, ordinary reads, app mutation, reconnect and
   cold recovery separately; do not generalize a repeated warm-query result.
5. Keep evidence bounded and publish handoffs at batch boundaries or meaningful
   failures. Do not spend each small helper change on another broad checkpoint
   or repeat already-green gates without changed code or a new concern.

The first preview may expose incomplete features honestly; completion of the
full platform goal still requires all parallel journeys. No deployed preview,
browser authorization or real-model integrated session is established by this plan.
